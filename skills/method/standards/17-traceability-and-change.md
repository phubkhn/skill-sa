# Standard 17 — Traceability & Change Management

## Why

An architecture you cannot interrogate is an architecture you cannot safely change. Every element of the design must answer: *what caused you to exist, and what breaks if you change?*

## Trace ID

`TR-<scope>-<NNN>` — scope is the feature/initiative slug; NNN is zero-padded and sequential within scope.

**Origin rule:** a trace-id is minted **once**, at the point where a real-world change enters the system — a new requirement, a change request, an incident, a compliance obligation, or an SA-originated decision with no upstream request. Every artifact produced because of that change **reuses the same id**. Never reissue, never branch the id.

**Next sequence:**
```
grep -rho "TR-<scope>-[0-9]\{3\}" docs/architecture | sort -u | tail -1
```
Increment; start at `001`.

## Change classification

| Type | Meaning | Requires |
|---|---|---|
| `Initial` | first version of the artifact | — |
| `Update` | refinement or correction inside existing scope | — |
| `Change Request` | new or altered scope driven by a stakeholder ask | `cr-ref` |
| `Corrective` | change driven by a defect, incident, or review finding | `finding-ref` |

Classification is decided **once, at origin**, and propagated unchanged downstream. A skill may *propose* a classification from the diff, but the human confirms it — the diff does not know intent.

## Where trace data lives

| Location | Fields |
|---|---|
| Artifact header block | `Trace ID`, `Change Type`, `CR Ref` |
| `_logs/.design-log` | `trace-id`, `change-type`, `cr-ref`, `delta`, `stale-downstream` |
| `_logs/.trace-index.md` | one row per trace-id → all artifacts it touched |
| ADR | `Trace ID` + `Drivers addressed` |
| Risk register | `Trace ID` of the change that introduced the risk |

## Trace index

`_logs/.trace-index.md` is regenerated by `/sa:trace`:

| Trace ID | Origin | Type | Date | Artifacts touched | Status |
|---|---|---|---|---|---|
| TR-checkout-014 | CR-882 "add express lane" | Change Request | 2026-08-09 | intent v3, drivers v2, ADR-0009, container-checkout v4, flow express-lane v1 | In Review |

## Impact query

```
grep -rn "TR-<scope>-<NNN>" docs/architecture
```

Returns every artifact that decision touched, in one command. If an artifact appears in the design but not in any trace, it is **orphaned** — either its origin was never recorded, or it should not exist. `/sa:trace --orphans` reports these.

## Staleness propagation

When an artifact changes, its downstream dependents become **stale**, not wrong. The dependency direction is fixed by `standards/00-sa-journey.md`:

| Changed | Becomes stale |
|---|---|
| intent | drivers, impact, all designs |
| drivers | impact, ADRs, crosscutting designs, review |
| ADR | HLD, LLD, interfaces |
| HLD | flows, LLD, interfaces, review |
| LLD | interfaces, handoff |
| interface | handoff, any consumer's LLD |
| data | LLD, security, migration |

Staleness is recorded in `.design-log` under `stale-downstream` and reported by `/sa:trace --stale`. Stale artifacts are not silently regenerated — the SA decides.
